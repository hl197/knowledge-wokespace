## 1. 背景与问题

- 问题：AI 生成的技能、知识、用户偏好、项目资料和其他产出分散在聊天与本地文件中，难以统一保存、检索、追溯和复用。
- 目标用户与场景：用户本人在 Windows 本机上使用；工作台作为独立桌面应用，供本人查看，也供本机 AI 助手读取和新增内容。
- 当前做法与痛点：已有桌面 UI 原型和 SQLite 初始化，但卡片主要来自前端示例数据，持久化回读、文件导入、完整搜索和 AI API 尚未形成完整闭环。

## 2. 目标与成功标准

- 目标：建立本地优先的卡片化 AI 资产工作台，完成“新增/导入 → 持久化 → 回读 → 搜索 → 助手访问”的数据闭环。
- 成功标准：
  - 关闭并重新启动应用后，已保存卡片仍然存在。
  - 卡片正文保存为 Markdown，SQLite 保存索引、标签、来源、状态和路径。
  - 关键词可以检索标题、摘要、标签和正文。
  - Markdown/TXT 导入后同时保留工作台副本和原始文件路径。
  - 本机 AI 助手可以查询、新增和按明确授权修改卡片；不提供删除能力。
  - API 仅监听 `127.0.0.1`，不暴露到局域网。
  - TypeScript 构建、Rust 检查、相关测试和结构健康检查通过。

## 4. 核心需求

### P0 必须完成

- RQ-001：卡片持久化与回读
  - 验收：通过 UI 新建卡片后，关闭并重新启动桌面应用，卡片标题、类型、摘要、标签、状态和正文仍可展示。

- RQ-002：Markdown 与 SQLite 双写
  - 验收：每张新增或导入卡片都有对应 Markdown 文件；SQLite 存在对应索引记录和内容路径；任一写入失败时向用户显示错误，不静默成功。

- RQ-003：真实卡片列表与详情
  - 验收：列表和详情数据来自本地持久化层；示例数据不覆盖已有真实数据；卡片详情可显示正文、标签、来源、状态和更新时间。

- RQ-004：关键词搜索
  - 验收：输入关键词后，能返回标题、摘要、标签或正文包含该关键词的卡片；无结果显示空状态；搜索异常显示可理解的错误提示。

- RQ-005：标签、类型、收藏和状态筛选
  - 验收：用户可以按内容类型、标签、收藏状态和卡片状态筛选；筛选结果数量与实际展示一致。

- RQ-006：Markdown/TXT 导入
  - 验收：导入有效 Markdown 或 TXT 后，生成一张卡片；工作台保留副本；卡片记录原始绝对路径和来源类型；导入失败不生成半成品索引。

- RQ-007：本机 API 查询
  - 验收：`GET /api/health` 返回服务状态；`GET /api/cards` 支持关键词、类型、标签和状态筛选；`GET /api/cards/:id` 返回单卡详情；服务只监听 `127.0.0.1`。

- RQ-008：本机 API 新增与修改
  - 验收：`POST /api/cards` 可以新增卡片；`PATCH /api/cards/:id` 可以修改允许修改的字段；已有卡片不能通过 API 删除；请求失败返回明确的非 2xx 错误和原因。

- RQ-009：来源与状态记录
  - 验收：AI 或 API 新增内容记录来源、创建时间和状态；默认状态为草稿或待验证；修改操作保留更新时间。

- RQ-010：验证与结构检查
  - 验收：TypeScript 构建、Rust 检查和本轮相关测试通过；P0 完成后完成一次只读结构健康检查，并记录“继续交付/局部重构/架构调整/回到需求”的结论。

## 5. 用户流程与异常情况

- 主流程：打开工作台 → 浏览或搜索 → 新建/导入卡片 → 写入本地数据 → 查看详情 → 关闭并重启 → 验证内容仍存在。
- AI 流程：本机助手查询 → 获取卡片摘要或正文 → 新增/修改请求 → 工作台校验字段和权限 → 写入 Markdown/SQLite → 返回结果。
- 空状态：没有卡片、搜索无结果、筛选无结果时显示说明和下一步操作。
- 加载状态：首次加载、搜索和导入期间显示明确的加载状态，不重复提交。
- 错误/边界情况：文件不可读、路径不存在、重复导入、Markdown 写入失败、SQLite 写入失败、非法卡片 ID、空标题、超长正文、API 请求字段缺失、端口占用。

## 18. 工作台 UI 改造需求

### 已确认方向

- 主要界面类型：Explore + Command/Inspect；首屏核心动作是浏览不同类型的知识资产。
- 视觉语言：暗色沉浸式知识空间的设计语言，同时支持暗夜墨蓝、暖白纸张、琥珀暖色三套预设，并允许在预设基础上调整主色。
- 信息密度：中等密度，保留留白和视觉层次。
- 主布局：左侧主导航 + 顶部全局搜索/命令入口 + 内容区卡片；详情采用全屏详情页，返回后保留列表滚动位置。
- 导航入口：总览、全部内容、技能、知识、项目资料、AI 产出、收藏、最近更新、回收站。
- 卡片语言：内容图鉴型，使用视觉锚点、类型和标签辅助浏览。
- 详情页：顶部显示类型、状态、收藏、更新时间；正文、标签、来源、版本、关系分区展示。
- 搜索与命令：顶部搜索框 + 命令面板，支持关键词、类型、标签、收藏和状态筛选。
- 动效：明显动效、粒子/视差/光效/转场，但必须提供减少动效和低性能降级路径。
- 视觉资产：抽象知识地图、纸张、光晕纹理，只作为背景/封面/空状态，不承载核心数据。
- 原型：先制作 3 个可点击草图，比较布局和交互，不用颜色差异干扰判断。

### 3D 依赖与边界

- 用户已确认安装 `three`、`@types/three`、`@react-three/fiber`。
- 第一轮只实现轻量 3D 背景；不安装 `drei`，不实现 3D 知识节点图。
- 3D 仅为视觉层，不进入核心数据、搜索、备份或关系模型。
- 必须提供 CSS/Canvas 2D 降级，并支持 `prefers-reduced-motion`。

### 本轮非目标

- 不新增后端数据模型或 API。
- 不把个人数据用于生图或外部视觉服务。
- 不在第一轮实现完整 3D 知识空间。

- 用户选择混合方向：方向一的空间氛围与动效 + 方向三的内容图鉴卡片 + 方向二的命令/筛选效率。
- 正式实现先完成主题 Token、主布局、主题切换和卡片视觉层；随后接入全屏详情、命令面板、版本/关系/回收站 UI。
