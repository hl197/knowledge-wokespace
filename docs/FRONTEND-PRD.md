# 我的 AI 工作台前端 PRD

> 文档类型：前端视觉与交互 PRD
> 版本：0.13
> 状态：当前 UI 基线已完成，进入通用设计资源与前端技能整合迭代
> 项目：个人 AI 工作台
> 技术栈：React + TypeScript + Vite + Tauri
> 数据边界：真实个人数据仅保存在本机；视觉资产不承载个人数据，不上传 GitHub

## 1. 背景与问题

当前工作台已经具备本地卡片、搜索、导入、版本、回收站、审计和关系等功能底座。前端已开始实施主题系统、内容图鉴卡片、全屏详情、命令面板、主视觉、Spotlight Card 风格聚光和 Three.js 粒子氛围，但还未完成完整的视觉资产、组件编排、关系添加、状态界面与最终视觉验收。

本次前端改造要把工作台从“功能可用的本地卡片工具”升级为：

> 一个可浏览、可检索、可阅读、可操作，并具有独特视觉世界观的个人 AI 知识资产空间。

## 2. 目标用户与核心场景

- 用户本人在 Windows 桌面端浏览、检索和阅读个人 AI 资产。
- 用户通过技能、知识、项目资料和 AI 产出分类快速探索内容。
- 用户进入一张卡片后查看正文、来源、版本和关系。
- 用户通过搜索、筛选和命令面板快速定位资产。
- 用户在不同主题和视觉模式间切换，但不改变核心数据。

## 3. 设计定位

### 3.1 主界面类型

- 首要类型：Explore，探索和浏览知识资产。
- 次要类型：Command/Inspect，搜索、命令、详情检查和内容操作。

本产品不是营销首页，不采用“居中 Hero + 三张均等功能卡片”的默认模板。Hero 视觉只作为展厅入口，核心内容仍然是资产浏览和操作。

### 3.2 世界观

数字博物馆与东方未来图书馆的融合：

- 每张卡片像一件可收藏、可探索的知识展品。
- 页面像一个有展厅、展柜、灯光和空间层次的数字博物馆。
- 东方元素采用原创提炼，不复制具体古建筑、名画、古籍或品牌界面。
- 视觉方向融合宋式雅集的留白、木格、宣纸、深棕、茶色、青玉和现代数字光效。

### 3.3 视觉目标

- 明亮：不使用全屏沉重黑暗遮蔽内容。
- 温暖：使用象牙白、深棕、茶色、琥珀、铜色等材质语言。
- 科技：使用青绿色、青玉色、全息光、轨道、粒子和数字展品。
- 艺术：使用高端 3D 概念艺术、展陈构图、材质、光影和留白。
- 特色：避免普通 SaaS 卡片、无意义渐变、泛滥毛玻璃和模板化图标布局。

## 4. 已确认的视觉与交互决策

### 4.0 设计系统与事实状态

当前已实现（仍需最终运行态验收）：

- 三套主题预设、用户主色和减少动效设置，本机 `localStorage` 持久化；
- 东方数字图书馆主视觉资源与 Hero 视觉层；
- 内容图鉴型卡片、按类型区分的抽象展品封面、Spotlight Card 风格鼠标聚光；
- 基于 `three` 与 `@react-three/fiber` 的 Hero 粒子氛围；
- 全屏详情页、版本历史读取、关系展示、回收站/归档操作；
- 基础 `Ctrl/Cmd + K` 命令面板。
- 已验证卡片使用青玉 Border Beam 风格边缘光，收藏卡片使用琥珀 Border Beam 风格边缘光；普通卡片不持续闪烁。
- 已生成并接入技能、知识、项目资料、AI 产出四类抽象展品封面；资源仅作为视觉层。

- Border Beam 风格已应用到已验证/收藏展品；四类展品封面已生成并接入；关系添加表单已接入并支持重复关系提示。

未完成项不得在验收时表述为已交付，详见第 8 节。

### 4.1 主题系统

提供三套展厅预设，并允许调整主色：

1. 暗夜墨蓝 / 数字夜馆
2. 暖白纸张 / 东方明亮展厅
3. 琥珀暖色 / 铜色收藏展厅

主题设置包括：

- 主题预设；
- 主色调；
- 减少动效；
- 设置仅保存到本机 `localStorage`，不写入卡片数据库。

### 4.2 主布局

- 左侧主导航；
- 顶部全局搜索和命令入口；
- 顶部主题、导入和新建入口；
- 主内容区显示内容图鉴卡片；
- 卡片点击进入全屏详情；
- 返回后保留列表筛选和浏览上下文。

### 4.3 主导航

- 总览
- 全部内容
- 技能
- 知识
- 项目资料
- AI 产出
- 收藏
- 最近更新
- 回收站

### 4.4 卡片

卡片采用“内容图鉴 + 数字展品”语言：

- 顶部视觉封面或抽象展品；
- 类型、状态和收藏操作；
- 标题、摘要、标签、来源和更新时间；
- 视觉封面不得把个人正文或隐私数据发送给外部生图服务；
- Spotlight Card 鼠标聚光效果；
- 后续可加入 Tilted Card 或 Border Beam，但要评估阅读干扰。

### 4.5 详情页

全屏详情页包含：

- 类型、状态、收藏、更新时间；
- 正文阅读；
- 标签；
- 来源和原始路径；
- 版本历史与二次确认恢复；
- 关联卡片；
- 回收站恢复；
- 归档/取消归档。

正文阅读时应自动降低背景动效，保证阅读优先。

### 4.6 命令面板

通过 `Ctrl/Cmd + K` 或搜索框打开，支持：

- 浏览全部内容；
- 打开技能；
- 打开知识；
- 切换主题；
- 新建卡片；
- 刷新本地数据；
- 后续扩展类型、标签、收藏和状态筛选。

## 5. 组件与资源策略

外部资源采用按需研究、复制和改造，不整套安装组件库。

### 5.1 已研究资源

| 资源 | 适用方向 | 使用策略 |
|---|---|---|
| React Bits | Spotlight Card、Tilted Card、Particles、Light Pillar、Animated List | 按需复制/改造具体组件；已应用 Spotlight Card 风格和 Three 粒子背景方向 |
| Magic UI | Magic Card、Border Beam、Light Rays、Animated Grid、Blur Fade | 后续按需选组件；不直接引入完整库 |

| image_generate | 主视觉、类别封面、空状态和纹理 | 只使用抽象提示词，不包含个人数据 |

## 7. 动效与空间体验

### 7.1 动效节奏

采用“明显但有节奏”：

- 首屏进入：展厅淡入、光影和粒子出现；
- 卡片悬停：Spotlight、轻微位移、边缘高亮；
- 筛选：内容渐隐/渐入和布局稳定过渡；
- 详情：展品到详情的空间转场；
- 主题切换：背景、灯光和材质平滑过渡；
- 正文阅读：自动安静，降低或停止非必要背景动画。

### 7.2 3D 策略

不把 3D 限制为“只能轻量”，但按视觉收益分层：

- 展厅氛围层：粒子、光柱、轨道和抽象光效；
- 展品层：局部 3D 抽象展品或卡片倾斜；
- 空间层：未来可做关系/知识空间，但不作为当前首轮必需。

每层都要具备：

- CSS/Canvas 或静态图降级；
- 减少动效模式；
- 小窗口或低性能设备可用；
- 不影响正文、搜索和操作；
- 不把个人数据放入 WebGL 场景。

## 9. 性能与可访问性要求

- 初始页面不能因视觉效果阻塞核心卡片显示。
- Three.js/Canvas 视觉层不得阻塞搜索、筛选和详情操作。
- 根据真实运行结果决定是否懒加载 3D；不得只凭理论判断。
- 支持 `prefers-reduced-motion` 和应用内“减少动效”。
- 交互控件有可见 focus 状态和语义标签。
- 收藏、返回、主题、命令和恢复按钮可使用键盘操作。
- 移动/窄窗口下仍可浏览卡片和打开详情。
- 重要正文和操作文字满足可读对比度。
- 图片使用合适的 `alt` 或明确标记为装饰性背景。

## 10. 验收标准

### 视觉

- 首屏能明确呈现“数字博物馆/东方未来图书馆”世界观。
- 不是普通三列 SaaS 卡片页面。
- 主视觉明亮、温暖、有艺术气息，并具有科技细节。
- 至少有一种可感知的卡片互动效果和一种首屏空间效果。
- 三种主题切换后仍保持设计系统一致。

### 交互

- 卡片悬停、点击、收藏和详情流程真实可用。
- 命令面板可用快捷键打开和关闭。
- 主题、主色和减少动效可实时生效并在刷新后保留。
- 版本恢复有二次确认。
- 正文阅读时动画明显降低，不干扰阅读。

### 工程

- `npm run build` 通过。
- `cargo check` 和相关 Rust 测试通过。
- 运行态前端和 API 正常。
- 不改变已确认的数据权限和本地存储边界。
- UI 资源、外部组件和新增依赖有来源与许可证记录。
- 完成视觉、可访问性、响应式和性能检查。

### 组件与资源

- 每个接入的外部组件记录来源、许可证、具体用途、依赖和降级方案。
- 优先复制/改造单个开源组件；不因为视觉需求直接安装完整组件库。
- `motion` / `framer-motion`、`@react-three/drei` 或其他新依赖必须在实际需要时单独说明、确认并回归验证。
- 生图资产使用抽象提示词；生成前用户已确认使用外部生图服务；入库前必须可见复核。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 视觉过暗或展品不可读 | 使用明亮主题、对比遮罩和可读性验收 |
| 3D/粒子导致首屏过重 | 实测后懒加载、降级或降低粒子密度 |
| 动效干扰正文 | 详情阅读自动安静，支持减少动效 |
| 生图风格不稳定 | 先生成候选，选择后再批量生成；保留原图 |
| 组件库依赖膨胀 | 采用按需复制/改造，不整包安装 |
| 传统元素变成普通古风 | 只提炼材质、构图和留白，加入数字艺术和现代展陈 |
| UI 视觉改动破坏真实数据 | 视觉层与 API/数据层分离，先运行构建和真实回读 |

## 22. 前端需求讨论与结构化提示词流程

### 22.1 设计决策原则

### 22.2 设计树

所有中大型前端改造按以下设计树逐步收敛：

```text
界面用途
→ 核心用户动作
→ 信息层级
→ 内容密度
→ 视觉方向
→ 主题/字体/Token
→ 交互方式
→ 动效强度
→ 插画/材质/3D 资产

```

## 24. 炫酷版沉浸式数字展馆改造方案

### 24.1 新设计 Brief

- 世界观：沉浸式数字展馆；大场景、空间镜头、漂浮展品、粒子、光柱和抽象材质。
- 核心动作：展品探索；用户通过鼠标、滚轮、点击、筛选和命令入口探索内容。
- 信息效率：搜索、筛选、阅读、收藏、版本、关系和备份始终可用，视觉层不得阻塞。
- 视觉气质：高级冷峻、精密网格、强对比光束、克制排版和数字艺术展馆感。
- 材质：玻璃、金属、玉石、光柱、粒子、轨道和漂浮档案；不使用具体人物和复杂写实模型。
- 动效节奏：持续慢动 + 交互瞬时加速；平时缓慢漂浮，交互时增强反馈，再平稳回落。
- 三套主题：
  - 夜馆：深墨蓝 / 暗紫 / 电光蓝；
  - 白昼展厅：象牙 / 雾灰 / 青玉；
  - 铜色收藏馆：深木 / 棕黑 / 琥珀金。
- 文案：保留现有东方数字图书馆名称和核心文案，只升级视觉、空间和交互。

### 24.2 3D 场景分层

- 主场景层：Hero 使用完整但可控的抽象展品空间，包括粒子、光柱、轨道和漂浮体块。
- 展品层：卡片使用轻量 3D 展品效果、Tilt、Glare 和状态流光，不把所有卡片变成重型场景。
- 关系层：关系星图单独按需懒加载，打开后支持节点筛选、聚焦和返回详情。
- 降级层：首屏先显示静态背景/低成本场景；重型 3D chunk 在需要时加载；无 WebGL 时保留 CSS/Canvas 和列表。

### 24.3 交互状态机

```text
idle
→ slow-drift（展品/粒子缓慢运动）
→ pointer-near（镜头轻微偏移、卡片聚光）
→ hover（重点展品 Tilt/Glare/边框流光）
→ interact（点击/滚轮时镜头或展品短时加速）
→ transition（展品放大进入详情/关系空间）
→ settle（回到低频慢动）
```

规则：

- 普通卡片只使用轻量 hover/流光；
- 收藏/已验证/重点展品才使用强层级效果；
- 键盘 focus 必须有等价静态高光，不依赖 hover；
- 触屏不依赖 hover，使用点击反馈；
- 搜索、命令和业务按钮不等待场景状态机完成。

### 24.4 动态加载和包体方案

- 主页面：静态 Hero + 低成本 CSS/Canvas 层先渲染；
- `MuseumAtmosphere`：继续保持独立懒加载；
- 轻量展品：按卡片可见性或重点状态加载，不在首屏创建大量独立 Mesh；
- 关系星图：独立 dynamic import，仅点击“关系空间”时加载；
- 重型材质/模型：禁止进入首屏；需要时单独 chunk 和资源预算；
- 加载状态：展示静态展品骨架和明确文案，失败时保留列表/详情。

关系空间 chunk：独立加载，不进入初始页面

## 26. 炫酷版提示词与重新设计规范

### 26.1 重新设计授权

本项目允许在后续迭代中重新设计现有视觉方案，不把旧版 Hero、配色、卡片样式、动效或页面构图视为不可改变的硬约束。

不可擅自改变的边界仅包括：

- 本地数据优先和个人数据不上传；
- 现有搜索、筛选、阅读、收藏、版本、关系、回收站、备份和导入能力；
- 已确认的权限、审计和删除策略；
- 键盘、触屏、窄屏和必要的可访问性能力；
- 用户在新一轮 grilling 中明确保留的内容。

### 26.2 标准化前端提示词

以后所有中大型前端改造，在 grilling 收敛后必须生成详细、规范、可执行的设计/实现 Brief，不得只使用“更炫酷”“更高级”“更有科技感”等模糊表达。

标准提示词必须包含：

```text
Project goal：项目目标与用户最终结果
Target surface：页面/产品表面类型
User outcome：用户完成什么动作、获得什么结果
Primary actions：主要用户动作和次要动作
Information architecture：信息架构、层级、密度和焦点顺序
Visual world：世界观、情绪、参考原则和明确反例
Composition：构图、布局、空间关系、首屏焦点和响应式变化
Material and lighting：材质、光照、阴影、纹理、粒子和色彩行为
Typography：字体、字重、字号层级、字距和阅读规则
Theme system：主题、Token、状态色和主题切换规则
Component inventory：组件清单和组件之间的关系
Component states：default/hover/focus/loading/empty/error/success/disabled
Motion timeline：入场、悬停、点击、滚动、转场和 settle 状态
Motion parameters：触发器、持续时间、缓动、延迟、幅度、打断和清理
3D/Canvas/SVG assets：用途、数量、模型/纹理来源、静态降级
Resource candidates：候选资源和匹配理由
Official lookup plan：需要访问的官方源页和要核对的字段
License/dependency gate：许可证、新依赖、包体、GPU/内存和回滚
Technical stack：框架、渲染方式、模块边界和数据接口
Loading/performance：懒加载、分包、首屏预算、低性能设备策略
Accessibility：键盘、focus、触屏、reduced-motion、无 WebGL 和无脚本行为
Data/privacy：数据/API/本地存储/隐私边界
In scope：本次要做
Out of scope：本次不做
Risks and rollback：风险、失败处理和回滚方式
Acceptance criteria：可二元判断的验收标准
```

### 26.3 生成和执行顺序

```text
grilling 分轮设计树
→ Agent 总结共同理解
→ Agent 生成标准化提示词
→ 用户确认 Brief
→ 读取资源卡片 description
→ 判断主题/页面/技术栈匹配
→ 回到官网源头获取具体组件
→ 小切片实现
→ 构建/运行态/交互/性能验收
→ 再进入下一切片
```

### 26.4 炫酷效果的质量标准

炫酷不等于所有元素同时运动。正式实现必须建立视觉层级：

- 主视觉层：负责空间世界观和第一焦点；
- 重点交互层：负责展品、卡片和转场反馈；
- 业务效率层：搜索、筛选、阅读和管理保持稳定；
- 状态反馈层：使用短时、可理解、可打断的动效。

每一个高强度效果都必须回答：

```text
它帮助用户理解什么？
它由什么动作触发？
它持续多久？
它如何被打断？
低性能/键盘/触屏/无 WebGL 时如何工作？
```
